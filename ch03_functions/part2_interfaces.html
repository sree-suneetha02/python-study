§ 4.1

The jupyturtle Module

The jupyturtle module provides a tiny canvas and a virtual turtle you can steer with code. Three core commands get you moving: forward, left, and right.

from jupyturtle import make_turtle, forward, left make_turtle() forward(50) left(90) forward(50)

make_turtle creates the canvas and places a turtle at the centre facing east. forward(n) moves it n units, drawing a line behind. left(deg) rotates it counter-clockwise.

forward → left 90° → forward
§ 4.2

Making a Square

Repeating forward + left(90) four times closes a square. A for loop keeps it concise.

make_turtle() for i in range(4): forward(50) left(90)
50 × 50 square
§ 4.3

Encapsulation & Generalization

Encapsulation means wrapping working code in a function and giving it a name. Generalization means replacing hard-coded values with parameters so the function works in more situations.

def polygon(n, length): angle = 360 / n for i in range(n): forward(length) left(angle)

One function, infinite polygons — from triangles to near-circles.

polygon(n, 40) — n = 3, 5, 7

Encapsulation

Wrap a working snippet in a def, give it a clear name. Now it's reusable and self-documenting.

Generalization

Replace magic numbers with parameters. A square(50) becomes polygon(n, length).

Keyword Arguments

Call with names for clarity: polygon(n=7, length=30). Order doesn't matter.

§ 4.4

Approximating a Circle

A circle is just a polygon with many tiny sides. Compute the circumference, divide by the number of sides, and let polygon do the rest.

import math def circle(radius): circumference = 2 * math.pi * radius n = 30 length = circumference / n polygon(n, length)
circle(radius=50) — 30 segments
§ 4.5

Refactoring

When you discover a more general pattern — like polyline — you can restructure existing functions to use it. This is refactoring: improving internal structure without changing external behavior.

def polyline(n, length, angle): for i in range(n): forward(length) left(angle) def polygon(n, length): polyline(n, length, 360 / n) def arc(radius, angle): arc_length = 2 * math.pi * radius * angle / 360 n = 30 length = arc_length / n polyline(n, length, angle / n) def circle(radius): arc(radius, 360)
polygon + arc + circle → snail

Refactoring is a sign you've learned something. It doesn't mean the first draft was wrong — it means you now understand the problem better.

When circle calls arc, which calls polyline, each function gets its own frame on the call stack. Parameters with the same name (like angle) are local — different variables in different frames.

§ 4.7

A Development Plan

The encapsulation-and-generalization workflow:

  1. Start with a small, working program — no functions yet.
  2. Identify a coherent piece, wrap it in a function, give it a name.
  3. Add parameters to make the function more general.
  4. Repeat until you have a set of clean, working functions.
  5. Look for refactoring opportunities — shared logic, better abstractions.

Every function has two sides: its interface (name, parameters, purpose) and its implementation (how it does the work). You can swap implementations without changing the interface.

§ 4.8

Docstrings

A docstring sits at the top of a function and documents the interface — what it does, what each parameter means, and what types are expected.

def polyline(n, length, angle): """Draws line segments with the given length and angle between them. n: integer number of line segments length: length of each segment angle: angle between segments (degrees) """ for i in range(n): forward(length) left(angle)

If a function is hard to document, that's a signal the interface could be improved.

§ 4.9

Debugging with Conditions

An interface is a contract. Preconditions are what the caller promises (valid arguments). Postconditions are what the function promises in return (correct effects). When something breaks, check which side violated the contract.

Precondition

A requirement the caller must satisfy before invoking the function. E.g., n must be a positive integer.

Postcondition

A guarantee the function upholds when it finishes. E.g., drawing the correct number of segments.

§ 4.10

Glossary

encapsulation
Wrapping a sequence of statements inside a function definition.
generalization
Replacing specific values with parameters to make a function more broadly useful.
keyword argument
An argument that includes the parameter name, e.g. polygon(n=7, length=30).
refactoring
Restructuring working code to improve design without changing behavior.
interface
How a function is used — its name, parameters, and purpose.
implementation
How a function accomplishes its task internally.
docstring
A triple-quoted string at the start of a function that documents its interface.
precondition
A requirement the caller must meet before invoking a function.
postcondition
A guarantee the function provides upon completion.
development plan
A structured process for writing programs — here, encapsulation & generalization.
