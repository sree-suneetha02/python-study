Section 3.1

Defining New Functions

A function definition gives a name to a sequence of statements so you can run them whenever you like. Here's the anatomy:

def keyword  print_lyrics function name(): header
print("I'm a lumberjack, and I'm okay.") body
print("I sleep all night and I work all day.")

The header starts with def, followed by the function name and parentheses, ending with a colon. The body is indented four spaces and can contain any number of statements.

Defining a function creates a function object but doesn't run it yet. To run it, you call it:

print_lyrics()
I'm a lumberjack, and I'm okay. I sleep all night and I work all day.

The def keyword tells Python you are about to define a new function. The name must follow the same rules as variable names (letters, numbers, underscores, not starting with a digit). Parentheses are required even if the function takes no arguments. The colon marks the end of the header. The indented block that follows is the body — all statements indented at the same level belong to the function.

Section 3.2

Parameters

A parameter is a variable listed inside the parentheses of a function definition. When you call the function, the argument's value gets assigned to it.

def print_twice(string): print(string) print(string)
print_twice('Dennis Moore, ')
Dennis Moore, Dennis Moore,

Calling print_twice('Dennis Moore, ') has the same effect as assigning the argument to the parameter and then running the body.

📥

Argument → Parameter

'Dennis Moore, ' is the argument. Inside the function it becomes string — the parameter.

🔄

Variables work too

line = 'Dennis Moore, '
print_twice(line)
The value of line gets assigned to string.

🧩

Multiple Parameters

Functions can have multiple parameters: def add(a, b):. Arguments are matched by position: add(3, 5)

Section 3.3

Calling Functions from Functions

Once a function exists, you can use it inside other functions. Here we build up "The Spam Song" one layer at a time:

def repeat(word, n): print(word * n) spam = 'Spam, ' repeat(spam, 4)
Spam, Spam, Spam, Spam,
def first_two_lines(): repeat(spam, 4) repeat(spam, 4) def last_three_lines(): repeat(spam, 2) print('(Lovely Spam, Wonderful Spam!)') repeat(spam, 2) def print_verse(): first_two_lines() last_three_lines()
print_verse()
Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, (Lovely Spam, Wonderful Spam!) Spam, Spam,
Key Idea

print_verse calls first_two_lines, which calls repeat, which calls print. Functions are building blocks — small pieces snap together to make complex programs.

Functions can call other functions, which can call more functions. This composition is the most powerful idea in programming — you build complex behavior from small, tested pieces.

Section 3.4

Repetition — The for Loop

A for statement (or loop) repeats a block of code. It starts with the keyword for, a variable, and the keyword in, followed by a sequence:

for i in range(2): print(i)
0 1

range(2) produces the sequence 0, 1. The loop assigns each value to i, runs the body, then loops back to the header for the next value.

Understanding range()

range(n) generates numbers from 0 to n-1. So range(5) gives 0, 1, 2, 3, 4 — five numbers total. This zero-based counting is consistent with Python's indexing system. You can also use range(start, stop) and range(start, stop, step).

Looping with functions

for i in range(2): print("Verse", i) print_verse() print()
Verse 0 Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, Spam, (Lovely Spam, Wonderful Spam!) Spam, Spam, Verse 1 Spam, Spam, Spam, Spam, ...

You can also put a loop inside a function to make it reusable:

def print_n_verses(n): for i in range(n): print_verse() print()

This combines parameters (controlling how many times) with loops (the repetition mechanism) — two powerful ideas working together.

Section 3.5

Variables & Parameters Are Local

A variable created inside a function is local — it only exists while the function runs. Once the function ends, the variable is destroyed.

def cat_twice(part1, part2): cat = part1 + part2 print_twice(cat) line1 = 'Always look on the ' line2 = 'bright side of life.' cat_twice(line1, line2)
Always look on the bright side of life. Always look on the bright side of life.
print(cat) # after the function ends
NameError: name 'cat' is not defined
Scope Rule

Outside a function, its local variables and parameters don't exist. cat, part1, and part2 are all invisible outside cat_twice. This scope rule prevents one function from accidentally interfering with another function's variables.

Why local? If every variable was accessible everywhere, large programs would be impossible to maintain — you'd constantly worry about accidentally changing a variable used by another part of the program. Locality is a feature, not a limitation.

Section 3.6

Stack Diagrams

A stack diagram shows which variables belong to which function. Each function gets a frame — a box with the function name and its local variables.

__main__
line1 → 'Always look on the '
line2 → 'bright side of life.'
↓ calls
cat_twice
part1 → 'Always look on the '
part2 → 'bright side of life.'
cat   → 'Always look on the bright side of life.'
↓ calls
print_twice
string → 'Always look on the bright side of life.'
↓ calls
print
? → 'Always look on the bright side of life.'

Reading from top to bottom: __main__ called cat_twice, which called print_twice, which called print. Each frame shows only the variables that belong to that function.

The stack diagram is called a "stack" because frames are added (pushed) as functions are called and removed (popped) as they return. The __main__ frame is always at the bottom — it represents the global scope of your program.

Section 3.7

Tracebacks

When a runtime error occurs inside a function, Python shows a traceback — the chain of function calls leading to the error, in the same order as a stack diagram.

def print_twice(string): print(cat) # bug! cat is local to cat_twice print(cat) cat_twice(line1, line2)
NameError Traceback (most recent call last) → cat_twice(line1, line2) → print_twice(cat) → print(cat) NameError: name 'cat' is not defined

The traceback reads bottom-to-top: the error happened in print_twice, which was called by cat_twice, which was called from the top level. This mirrors the stack diagram's frame order — the most recent call is at the bottom, closest to the error.

Tracebacks are your first debugging tool. They tell you exactly where the error occurred and the path your program took to get there. The last line of the traceback gives the error type and message. The lines above show the call chain — each function reading "File … line … in <module>" shows which function was entered.

Section 3.8

Why Functions?

Readability

Naming a group of statements makes your program easier to read and understand. A well-named function like calculate_total() is self-documenting.

Less Repetition

Eliminate duplicate code. Write it once, call it many times. Change it once, fix it everywhere.

Easier Debugging

Test and fix small pieces one at a time, then assemble them into a whole. If a function works in isolation, the bug is in how you call it.

Reusability

A well-designed function can be used across many different programs. Build a library of utilities over time.

Section 3.9

Debugging

🔍

Detective Work

You're given clues (error messages, wrong output) and must infer what went wrong. The traceback is your best clue.

🧪

Experimental Science

Form a hypothesis, modify the program, and check if the result matches your prediction. Repeat until the bug is found.

🪜

Small Steps

Start with working code and make small changes. If you're debugging a lot, you're writing too much code before testing.

Common Function Errors

  • NameError: Using a variable that doesn't exist in the current scope (e.g., referencing a local variable from outside)
  • TypeError: Wrong number or type of arguments passed to a function
  • IndentationError: The function body isn't indented consistently
  • Using a variable name that doesn't match a parameter name inside the function
  • Forgetting to call a function (writing print_twice instead of print_twice())
Section 3.10

Glossary

function definition
A statement that creates a new function, starting with def.
header
The first line of a function definition, ending with a colon.
body
The indented sequence of statements inside a function.
function object
The value created by a definition; the function name refers to it.
parameter
A name inside a function that receives an argument's value.
argument
The value passed to a function when calling it.
loop
A statement (for) that repeats one or more statements.
local variable
A variable created inside a function, accessible only there.
scope
The region of a program where a variable is accessible.
stack diagram
A visual showing function frames and their variables.
frame
A box in a stack diagram representing one function call.
traceback
The chain of function calls printed when an exception occurs.
composition
Using one function inside another to build complex behavior.
