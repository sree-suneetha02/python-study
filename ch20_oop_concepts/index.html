Overview

What is OOP?

Object Oriented Programming is a paradigm that organizes code using objects and classes to represent real-world entities. Each object has attributes (data) and methods (actions).

Concept 01

Class

A class is a blueprint for creating objects. It defines attributes (variables) and methods (functions) that its instances will have.

  • Created using the class keyword
  • Attributes are variables belonging to a class
  • Attributes are public and accessed via the dot (.) operator

Class Structure Diagram

Python class Dog: species = "Canine" # Class attribute def __init__(self, name, age): self.name = name # Instance attribute self.age = age # Instance attribute
Concept 02

Objects

An object is an instance of a class. It holds its own data and represents a specific entity built from the class blueprint.

Object Instantiation Flow

Python # Creating objects dog1 = Dog("Buddy", 3) dog2 = Dog("Luna", 5) print(dog1.name) # Buddy print(dog1.species) # Canine print(dog2.name) # Luna
  • State — represented by attributes, reflects object properties
  • Behavior — represented by methods, reflects responses to other objects
  • Identity — gives a unique name enabling interaction between objects
Core Principles

Four Pillars of OOP

These pillars form the foundation for designing structured, reusable, and maintainable software.

The Four Pillars

01

Inheritance

Allows a child class to acquire properties and methods from a parent class. This supports hierarchical classification and promotes code reuse, letting you build specialized classes on top of general ones.

02

Polymorphism

Means "same operation, different behavior." Functions or methods with the same name can work differently depending on the type of object they act upon — enabling flexible, interchangeable implementations.

03

Encapsulation

The bundling of data (attributes) and methods (functions) within a class, restricting access to some components to control interactions and protect internal state from unintended modification.

04

Data Abstraction

Hides internal implementation details while exposing only the necessary functionality. It helps you focus on "what to do" rather than "how to do it," simplifying complex systems.
