17.1

Representing Cards

A standard deck has 52 cards — four suits (Spades, Hearts, Diamonds, Clubs) and thirteen ranks (Ace through King). To make cards easy to compare, we encode suits and ranks as integers.

SuitCode
Clubs0
Diamonds1
Hearts2
Spades3

Face-card ranks are encoded as Jack = 11, Queen = 12, King = 13, and Ace can be 1 (low) or 14 (high). Two lists of strings serve as look-up tables:

class Card:
    """Represents a standard playing card."""

    suit_names = ['Clubs', 'Diamonds', 'Hearts', 'Spades']
    rank_names = [None, 'Ace', '2', '3', '4', '5', '6', '7',
                  '8', '9', '10', 'Jack', 'Queen', 'King', 'Ace']
Key idea: suit_names and rank_names are class variables — shared by every Card instance, accessed via Card.suit_names.

17.2

Card Attributes

The __init__ method stores integer suit and rank as instance attributes:

def __init__(self, suit, rank):
    self.suit = suit
    self.rank = rank

Creating and inspecting a card:

queen = Card(1, 12)
queen.suit, queen.rank   # (1, 12)

17.3

Printing Cards

A __str__ method translates integer codes back to human-readable names using the class variables:

def __str__(self):
    rank_name = Card.rank_names[self.rank]
    suit_name = Card.suit_names[self.suit]
    return f'{rank_name} of {suit_name}'
print(queen)   # Queen of Diamonds

17.4

Comparing Cards

By default, == checks identity (same object). We override this with __eq__ to check equivalence:

def __eq__(self, other):
    return self.suit == other.suit and self.rank == other.rank

For ordering, a helper converts a card to a tuple (suit, rank), and __lt__ compares those tuples:

def to_tuple(self):
    return (self.suit, self.rank)

def __lt__(self, other):
    return self.to_tuple() < other.to_tuple()
Totally ordered: With __eq__, __lt__, and __le__ defined consistently, any two cards can be compared — and a list of cards can be sorted.

17.5

Decks

A Deck wraps a list of Card objects. A static method generates all 52 cards:

class Deck:
    def __init__(self, cards):
        self.cards = cards

    @staticmethod
    def make_cards():
        cards = []
        for suit in range(4):
            for rank in range(2, 15):
                cards.append(Card(suit, rank))
        return cards
deck = Deck(Deck.make_cards())
len(deck.cards)   # 52

17.6

Printing the Deck

The __str__ method builds a list of individual card strings and joins them with newlines — more efficient than repeated string concatenation:

def __str__(self):
    res = []
    for card in self.cards:
        res.append(str(card))
    return '\n'.join(res)

17.7

Add, Remove, Shuffle & Sort

Thin wrappers around list methods:

def take_card(self):
    return self.cards.pop()

def put_card(self, card):
    self.cards.append(card)

def shuffle(self):
    random.shuffle(self.cards)

def sort(self):
    self.cards.sort()
Delegation: Deck.sort simply calls list.sort, which in turn uses the __lt__ method on Card.

17.8

Parents and Children

A Hand inherits from Deck — it reuses take_card, put_card, shuffle, and sort, but overrides __init__ to start with an empty list and a label:

class Hand(Deck):
    def __init__(self, label=''):
        self.label = label
        self.cards = []

move_cards is a polymorphic method that works between any combination of Deck and Hand objects:

def move_cards(self, other, num):
    for i in range(num):
        card = self.take_card()
        other.put_card(card)
Deck (parent)
↓ inherits
Hand (child)
↓ inherits
BridgeHand / PokerHand (grandchild)
Liskov Substitution Principle: Any code that works with a Deck should also work with a Hand. Child classes must honour the parent's interface.

17.9

Specialization

BridgeHand extends Hand with a scoring method specific to bridge:

class BridgeHand(Hand):
    hcp_dict = {'Ace': 4, 'King': 3, 'Queen': 2, 'Jack': 1}

    def high_card_point_count(self):
        count = 0
        for card in self.cards:
            rank_name = Card.rank_names[card.rank]
            count += BridgeHand.hcp_dict.get(rank_name, 0)
        return count

This is specialization — adding domain-specific behaviour while reusing the general-purpose base.

17.10

Debugging

Inheritance can scatter method definitions across multiple classes. To trace where a method is defined, use MRO:

def find_defining_class(obj, method_name):
    for typ in type(obj).mro():
        if method_name in vars(typ):
            return typ
    return f'Method {method_name} not found.'
find_defining_class(hand, 'shuffle')
# <class '__main__.Deck'>

17.11

Glossary

Inheritance Defining a new class as a modified version of an existing class.
Encode Mapping one set of values to another (e.g., suits → integers).
Class Variable A variable defined inside a class but outside any method; shared by all instances.
Totally Ordered Any two elements can be compared, and results are consistent.
Delegation When a method passes responsibility to another method to do the work.
Parent Class The class being inherited from.
Child Class The class that inherits from another class.
Specialization Using inheritance to create a class tailored for a specific use.
